KP 8.3 ROS基础
重点 ★★★★★

ROS（Robot Operating System，机器人操作系统）是当今最主流的机器人软件开发框架。它不是一个真正的操作系统，而是运行在Linux之上的中间件，提供了硬件抽象、消息传递、包管理等功能，使机器人软件开发更加模块化和可复用。当前ROS已发展到ROS 2版本，本节代码示例基于ROS 2（rclpy）编写。

ROS的三大核心通信机制：

  • 话题（Topic）：异步发布/订阅通信模式。Publisher发布消息到话题，Subscriber订阅话题接收消息。适合传感器数据流等持续数据传输。
  • 服务（Service）：同步请求/响应通信模式。Client发送请求，Server处理并返回响应。适合一次性查询（如获取机器人状态）。
  • 动作（Action）：支持反馈的异步通信模式。适合长时间执行任务（如导航到目标点），可中途取消并获取进度。

ROS常用的仿真与可视化工具：

  • rviz：三维可视化工具，可显示机器人模型、传感器数据、TF坐标变换树。是调试机器人状态的首选工具。
  • Gazebo：物理仿真器，可模拟机器人的动力学、传感器（激光雷达、相机）、环境碰撞。支持在虚拟环境中测试算法。

下面通过ROS 2的Python示例展示话题通信的编程实现：Publisher节点发布关节角速度指令，Subscriber节点订阅并打印接收到的消息。ROS 2采用面向对象的节点类（继承自Node），通过回调函数处理订阅消息。

Python ROS 2 Publisher节点（rclpy）
#!/usr/bin/env python3
# ROS 2 Publisher节点：发布关节速度指令
import rclpy
from rclpy.node import Node
from std_msgs.msg import Float64MultiArray

class JointCommander(Node):
    def __init__(self):
        super().__init__('joint_commander')
        # 创建Publisher，话题名/joint_vel，消息类型Float64MultiArray
        self.publisher_ = self.create_publisher(Float64MultiArray, '/joint_vel', 10)
        # 10Hz定时器回调发布消息
        self.timer = self.create_timer(0.1, self.timer_callback)

    def timer_callback(self):
        msg = Float64MultiArray()
        msg.data = [0.1, 0.0, 0.05, 0.0, 0.0, 0.0]
        self.publisher_.publish(msg)
        self.get_logger().info(f'发布关节速度: {msg.data}')

def main(args=None):
    rclpy.init(args=args)
    node = JointCommander()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    node.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
Python ROS 2 Subscriber节点（rclpy）
#!/usr/bin/env python3
# ROS 2 Subscriber节点：订阅关节速度并打印
import rclpy
from rclpy.node import Node
from std_msgs.msg import Float64MultiArray

class JointListener(Node):
    def __init__(self):
        super().__init__('joint_listener')
        # 创建Subscriber，订阅/joint_vel话题
        self.subscription = self.create_subscription(
            Float64MultiArray, '/joint_vel', self.listener_callback, 10)

    def listener_callback(self, msg):
        self.get_logger().info(f'接收到关节速度: {list(msg.data)}')

def main(args=None):
    rclpy.init(args=args)
    node = JointListener()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    node.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
💡 ROS 2 与 ROS 1 对比

ROS 2是ROS 1的下一代版本，主要改进包括：

  • 中间件：ROS 1使用自研的TCPROS协议，依赖ROS Master中心节点；ROS 2采用DDS（Data Distribution Service）工业标准中间件，去中心化，无需Master，节点可直接发现彼此。
  • 实时性：ROS 2支持实时优先级调度和QoS（服务质量）配置，满足工业控制的实时性需求；ROS 1无实时性保障。
  • 多机通信：ROS 2原生支持跨网段、跨平台（Linux/Windows/macOS）分布式部署；ROS 1仅限同一局域网且需配置ROS_MASTER_URI。
  • 生命周期管理：ROS 2引入节点生命周期（Lifecycle Node）机制，支持节点的受控启动、配置、激活、停用等状态转换，便于构建高可靠系统。
  • 安全性：ROS 2支持DDS Security层，提供认证、加密、访问控制等安全机制，适合工业和商用部署。
✓ ROS的工程价值

ROS的最大价值在于软件复用：导航、SLAM、运动规划等成熟算法以"包"的形式共享，开发者无需从零实现。ROS 2进一步引入了DDS中间件，提升了实时性和分布式部署能力，成为新一代机器人软件标准。

💡 rviz与Gazebo协作

在实际开发中，rviz和Gazebo通常配合使用：Gazebo提供物理仿真环境（机器人模型、传感器、碰撞），rviz订阅Gazebo发布的传感器话题进行可视化。开发者可以在rviz中查看激光雷达点云、相机图像、TF坐标树，同时在Gazebo中观察机器人在虚拟世界中的运动。这种"仿真+可视化"的组合是ROS开发的标准工作流。
